Scope: minigo competes on build + start + run, so a task that scans every file (grafana-openapi) can never beat go on run speed alone. These items exist to keep heavy scripts far from the ~3 min pain threshold and to keep the interpreter benchmark healthy; they rank below the pitch-validating "large target package through `inspect`" realworld task above. Ordered by realworld `grafana-openapi` on main 7c6e1ed3 (3.09–3.11 s, 2.09 GB allocated: `prepFrame` 700 MB, `methodWalkU` 359 MB, `frame.push` 244 MB, `runtime.Tag` 208 MB, `OpNewLocal` cells 112 MB, `OpFieldRef` 69 MB).   - [ ] **operand stack grows from empty on every call** (`frame.push`, 244 MB on grafana-openapi): record the chunk's max stack depth at compile time and allocate once (or slice a VM-owned stack). Toward the shared contiguous value stack listed under the last item.
  - [ ] **`runtime.Tag` allocates a fresh `*Named` per tagging** (208 MB on grafana-openapi): find the hot call sites (coercion/zero/assign re-tagging an already-tagged value with the same typedef) and reuse the existing box when the tag and value are unchanged.
  - [ ] **selector resolution re-searches by name**: `structMember` linearly compares field names then hits `Methods`; `FieldRef.find` walks embeddings breadth-first. Cache the resolved access path (`Def` + name → field index path / method) per type; a dynamic re-dispatch is still needed at interface-typed embedded fields. Also, `Decl.Doc`/`Field.Doc` keep the trailing `\n` — emitters must trim. Both are minor API-shape nits rather than bugs; unify or document the asymmetry.
- [x] **script arg boundary rejects `[]map[string]any` on spelling, and `[]any` elements arrive `*runtime.GoValue`-boxed** (extract-schema DescRules spike): `func Main(..., rs []map[string]any)` traps `cannot use []map[string]interface {} as []map[string]any` — the arg check is spelling-based (`interface {}` vs `any`, and `interface{}` vs `interface {}` flip the space). Passing `[]any` instead lands each element as an unindexable `*runtime.GoValue`. Only `[]string`/`[]byte`-shaped element types auto-unbox reliably; structured plugin data had to move to string spellings. Unify the spelling comparison or deep-unbox `[]any` elements.
- [x] **`inspect.Symbol(pkg, name)` traps on a missing name — no non-trapping lookup** (extract-schema desc-hook spike): optional plugin entry points (`DescField`/`DescDecl`) can only be probed by scanning `inspect.Decls` and matching name+kind by hand. A `Lookup`-style soft variant (nil on miss) would make "does this package export X?" a one-liner.
- [x] **`x.(*inspect.Field)`/`func(*inspect.Field, ...)` asserts fail on inspect view types — not registered, not interned** (extract-schema desc-hook spike): `inspect.Value(pp,"DescField").(func(*inspect.Field,string)string)` traps "interface conversion: ... types from different packages", and `x.(*inspect.Field)` inside a plugin traps `undefined: inspect.Field` — view types aren't type symbols. NOTE: source-package imports ARE interned across `inspect.DirOf` roots — `.(func(*extschema.Config))` asserts cleanly — so typed plugin contracts work; it's only the stub/intrinsic types that lack identity. Register the inspect view types (and intern them) so hooks can name `*inspect.Field` directly; until then `func(any,...)` + `reflect.FieldByName` is the workaround.
- [x] **a package's loading path (bound stub vs source index) changes its behavior — let callers choose** (extract-schema plugin spike): whether a package resolves through bound intrinsics or parsed source is decided per package and invisibly, but the consequences leak: `*inspect.Field`/`Decl` aren't interned while `*extschema.Config` is, `inspect.Standard()` is only true behind the bound shadow, `-stdlib leaf|walk` exists precisely because `time.Time` can't afford full parsing, and a symbol absent from the bind map traps `undefined` instead of falling through to source. An option to request "source interpretation only" (or "bound-only") per lookup/package would make the choice visible and let tools pin behavior instead of inheriting whatever the bound coverage happens to shadow — either as a load flag/mode on the existing entry points, or as **separate load functions** (e.g. a `DirOf`-source and a `BoundOf`-stub split) so the loading path is spelled in the call.
- [x] **extract-schema `-pkg` mode is dead: `inspect.DirOf(target)` runs before the pkgMode branch** (extract-schema corpus m04/m05, [minigo-usecasefuzz](https://github.com/podhmo/minigo-usecasefuzz) `extract-schema/`): the script calls `inspect.DirOf(target)` unconditionally, then only probes `inspect.PackageOf` inside the pkgMode check — so `-pkg example.com/m` and `-pkg time` both trap in `DirOf` on a non-directory string. Reorder so pkg mode skips `DirOf`, or soften `DirOf` itself (see next entry).
- [x] **`inspect.DirOf` traps on any unresolvable path — same hole as `inspect.Symbol`** (corpus m04/m05/m08/p06, sibling of the "no non-trapping lookup" entry above): `DirOf` on a missing dir, `-pkg` target string, or absent `-plugin` dir exits with `runtime trap: ...`; no soft variant exists, so tools cannot distinguish "no such dir" from "dir has no Go files" or degrade gracefully. Extend the non-trapping-`Lookup` ask to the dir/package loaders.
- [x] **generic type params resolve as package symbols → `inspect.Symbol: no T` trap** (corpus c06/c07/c11): `Box[T]` fields, generic type decls, and aliases to `Box[int]` all attribute `T` to the declaring package, so the schemaFor walk traps where gc keeps the param unbound. SymbolID needs a type-param marker (or the walk a bound-substitution surface — the `convert-define` generic-instantiation entry above is the same wall from the other side).
- [x] **`-stdlib walk` on packages with cgo files traps `cgo is not supported: import "C"`** (corpus l02): `inspect.SourceOf` on `net` dies on the first cgo-importing file instead of skipping it, making walk mode unusable for whole stdlib subtrees. Filter `import "C"` files the way `_test.go` files are filtered, or soften the failure per-file.
- [x] **`inspect.Value` hands scripts raw const cells — enum values never arrive as JSON scalars** (corpus n04/n05/l05): `Value` returns the const's `Elem`, so untyped int consts materialize as literal-text `UConst`s (`"1"`) and typed-bound consts (e.g. `time.Duration`) arrive as `*runtime.GoValue` and emit via `String()` (`"-2562047h47m16.854775808s"`); a struct-typed const emits `"{0 0}"`. Also `EnumMembersOf` misses members whose type is only inferred (`Microsecond = 1000 * Nanosecond`). Either the API returns materialized scalars or the members contract documents the wrapper types.
- [x] **`Sig.ParamFields` counts `*ast.Field` groups, not params — arity checks have holes** (corpus p05): `func TwoArgs(a, b *extschema.Config)` is one ParamField, so a plugin signature check written as `len(ParamFields) != 1` admits it and the later `.(func(*C))` assert panics `interface conversion`. A names-flattened param view (or a documented count-the-names recipe) would close the hole.
- [x] **extract-schema tool-side divergences found by the corpus** (recording only; fixes are example-side): `exported()` uses an ASCII `A-Z` check so non-ASCII exported fields vanish (n06); the recursive-embed rescue invents a `"TypeName"` property where `encoding/json` drops the subtree (e02); `json:",string"` and other tag options are ignored (t01); `jsonschema-override:"required=..."` silently no-ops (t03); `[]byte` maps to an array instead of JSON's base64 string (s02). Ideal outputs are pinned as DIFF wants in the corpus.
- [x] **extract-schema `-pkg` cannot resolve stdlib type names** (corpus m05, follow-up of the `-pkg` entry above): `-pkg time Time` exits FAIL with `type "Time" not found in time` — `inspect.LookupPackageOf` answers the bound host package (globals only, no source index), and `Main` never falls back to `inspect.SourceOf`, so source-level decls of bound stdlib paths are unreachable. Decide whether the -pkg loader should retry through `SourceOf` (and how that composes with `-stdlib leaf`) — expected verdict moves from today's graceful FAIL to a real schema once pinned. Resolved: `-pkg` retries bound shadows through `inspect.LookupSourceOf` — the `-stdlib` policy only governs named-type refs inside the walk, so leaf stays a ref-level choice.
- [x] **`*runtime.Package` has no typedef tag — engine-internal values bypass the tag system** (residual of #875): a `*runtime.Package` value belongs to no case in `typeOfValue`/`pointeeTag`/`Deref`, so `func() *runtime.Package` signatures assert/coerce only through the `HostNew`-native comparison added there. Runtime-internal values need a real typedef tag story (or a documented carve-out) rather than per-type host paths. Resolved: the opaque-handle class (`Package`/`TypeDef`/`Iterator`/`ImportRef`) synthesizes its tag through `internalTypedef` → `hostTypedefOf`, and `TypIdentical` compares host typedefs by native type, so tag funnels answer like any other pointer.
- [x] **`inspect.FileOf` / `inspect.SourceOf` have no soft `Lookup*` variant** (deferred from #866): `LookupDirOf`/`LookupPackageOf` return nil on miss, but the file and source loaders still trap; no corpus case hit them, so the variants were never built. Add `LookupFileOf`/`LookupSourceOf` if a caller needs graceful probing of single files or bound-shadowed source.
