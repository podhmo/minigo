- [ ] **Data-structure / algorithm-level performance candidates** (from a code review of the VM; land each separately with before/after numbers). Scope: minigo competes on build + start + run, so a task that scans every file (grafana-openapi) can never beat go on run speed alone. These items exist to keep heavy scripts far from the ~3 min pain threshold and to keep the interpreter benchmark healthy; they rank below the pitch-validating "large target package through `inspect`" realworld task above. Ordered by realworld `grafana-openapi` on main 7c6e1ed3 (3.09–3.11 s, 2.09 GB allocated: `prepFrame` 700 MB, `methodWalkU` 359 MB, `frame.push` 244 MB, `runtime.Tag` 208 MB, `OpNewLocal` cells 112 MB, `OpFieldRef` 69 MB). The last items only showed up on synthetic scripts (a `fib(27)` + 2M struct appends + 500k map updates micro-script allocated ~1.46 GB; whether GC dominates its wall time is unconfirmed — check with `go tool trace` / `GODEBUG=gctrace=1`):
  - [-] **non-param locals are allocated twice**: `prepFrame` pre-fills every slot past the params with `&Cell{NIL}` (190 MB on grafana-openapi), and `OpNewLocal` then replaces the cell with a fresh one (112 MB). Skip the pre-fill for slots that are always `OpNewLocal`-ed before use; check what relies on it first (named results, `goto` over declarations, iterator slots, `OpCoerce`). Landed: the pre-fill is now one shared `cells` block per frame (recycled for non-escaping chunks), not a cell per slot. Residual: `OpNewLocal` on a boxed slot still allocates a fresh `*runtime.Cell` per bind — required for variable identity when an earlier bind was captured (`f := func() { x }` then `x = v`); removing it needs per-slot capture analysis, not just "OpNewLocal-ed before use".
  - [-] **`runtime.Tag` allocates a fresh `*Named` per tagging** (208 MB on grafana-openapi): the prescribed reuse can't apply — every `Tag` call site passes a fresh payload, no already-tagged input (measured in #1298). The cost is fresh `&Named` boxes from binop result re-tagging (`runtime.Tag(tag, ru)` per op), const materialization and host-scalar boxing. Remaining: a bounded per-engine (typedef, scalar payload) → Named dedup table via a VM-side wrapper (Tag is package-level), or tagging fewer results (binop leaves the result untagged for the assign coerce to stamp — needs the type-rule audit).
  - [-] **selector resolution re-searches by name**: `structMember` linearly compares field names then hits `Methods`; `FieldRef.find` walks embeddings breadth-first. The OpSelect/OpSelectCall site cache now also covers `OpDeref` FieldRef reads (`x.f++`, `x.f op= y`), whose resolutions memoize per (TypeID, method-set epoch); the site cache now also covers namedMember (declared-method and payload-field/path resolutions replay as selNamedMethod/selField/selPath; ~20% wall on a 800k named-struct field-select microbench). Remaining: FieldRef.find embedding walks, dynamic iface dispatch — still uncached. Related: the `#485` selector lowering item above (`OpFieldRef` 69 MB, `FieldRef.find` ~3% CPU on grafana-openapi).
  - [-] **every local is a heap `*Cell`** (`OpNewLocal`, `prepFrame`): the `Boxed` per-slot classification landed — plain slots hold their value in `f.locals` and only `&x`/capture/pointer-receiver/unknown-member slots get cells. A transient store/select ref still promotes a plain slot (`localCell`), so a non-escaping chunk now lays the pooled cells block out one-per-slot and promotion reuses `cells[i]` — a `x.F = x.F + 1` per call microbench: 4.0M → 3.6M allocs, 73.6 → 65.6 MB. Remaining: escaping chunks still allocate the boxed-cell block per call (needs publish detection to pool), and a rebind on a promoted slot allocates a fresh `*Cell` (variable identity).
  - [-] **`append` builds a whole zero value to learn the element type** (`builtins.go`, `v.TypeOf(v.ElemZero(rtyp))`): `ElemZero` constructs e.g. a full `Struct` plus a fresh `zeroSeen` map on every append. The append element typedef now resolves lazily — only when an argument can need converting (untyped const, materialized scalar, untyped nil) — so composite-element appends never pay; the remaining `TypeOf(ElemZero)` call sites (the zero-size growth check, make(), the JSON paths) still construct a real zero by need. A direct element-typedef route remains open: `elemTypedef` is VM-internal, so add e.g. `VMCaller.ElemTypeOf(td)` and migrate the other users of the `TypeOf(ElemZero(td))` idiom the `VMCaller` doc prescribes (`intrinsics.go` JSON paths, `builtins.go`'s zero-size growth check and other `ElemZero` sites). Semantics: today's `et` is lossy (`typeOfValue` maps every integer kind to `int`, `float32` to `float64`, an interface element to nil, `type S string` to `string`) yet output matches go for `[]float32`/`[]S`/`[]any`/`[]int8` appends because later coercion fixes it — a precise typedef newly routes `Convert(any, UConst)` / `Convert(S, UConst)`, so verify by diffing program output against go (casefuzz/difffuzz pins), covering named types, aliases, generics and function-local types. Benchmark scalar, struct, and named/generic appends separately on pre-sized slices (`ns/op`, `B/op`, `allocs/op`), then a mixed run. Synthetic only: no measurable share on grafana-openapi (`append` + `zeroSeen` < 40 MB).
  - [-] **later / larger**: a shared contiguous value stack for frames (args without `popArgs` slices, no `BoundMethod` receiver prepend copy); memoizing typedef-derived info — each typedef's TypeID is now memoized per engine (typeid.go: -28% alloc space on the ZZWork microbench; element typedef and the `Zero` name switch remain)'s name switch) kept separate from full typedef interning; a tagged `Value` instead of `any` (int64 boxing was only ~62 MB of the 1.46 GB above); `orderSpecs` (`compile/compile.go`) picks the next spec in O(V²) — a heap would help large packages' first init only.
