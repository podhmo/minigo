- [x] **`convert-define`: `-file` errors and `c.Compute` type checks** (#48, found by a satisfaction evaluation): a missing or directory `-file` used to surface as `failed to run definition script: loading define file into interpreter: parse ...: no such file or directory`; `run` now checks it first and says `Fix the command-line arguments`. `c.Compute(dst.Value, src.N)` (int into string) passed `-strict` and failed at `go build`; the interpreter now records `ComputedField.ExprType` for the shapes knowable without go/types (a `src` field path, a non-generic package func with one result) and the generator warns on a mismatch, so `-strict` rejects it. Unknown shapes stay silent. Found while testing: packages referenced only inside a `c.Compute` expression were never recorded in `info.Imports` (goimports had been adding them; the integration test passed only because a `c.Convert` in the same define file registered the same package); the walker now registers every `pkg.Name` in the expression.
