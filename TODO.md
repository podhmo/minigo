- [ ] **Data-structure / algorithm-level performance candidates** (from a code review of the VM; land each separately with before/after numbers). Scope: minigo competes on build + start + run, so a task that scans every file (grafana-openapi) can never beat go on run speed alone. These items exist to keep heavy scripts far from the ~3 min pain threshold and to keep the interpreter benchmark healthy; they rank below the pitch-validating "large target package through `inspect`" realworld task above. Ordered by realworld `grafana-openapi` on main 7c6e1ed3 (3.09–3.11 s, 2.09 GB allocated: `prepFrame` 700 MB, `methodWalkU` 359 MB, `frame.push` 244 MB, `runtime.Tag` 208 MB, `OpNewLocal` cells 112 MB, `OpFieldRef` 69 MB). The last items only showed up on synthetic scripts (a `fib(27)` + 2M struct appends + 500k map updates micro-script allocated ~1.46 GB; whether GC dominates its wall time is unconfirmed — check with `go tool trace` / `GODEBUG=gctrace=1`):
  - [ ] **non-param locals are allocated twice**: `prepFrame` pre-fills every slot past the params with `&Cell{NIL}` (190 MB on grafana-openapi), and `OpNewLocal` then replaces the cell with a fresh one (112 MB). Skip the pre-fill for slots that are always `OpNewLocal`-ed before use; check what relies on it first (named results, `goto` over declarations, iterator slots, `OpCoerce`).
  - [ ] **operand stack grows from empty on every call** (`frame.push`, 244 MB on grafana-openapi): record the chunk's max stack depth at compile time and allocate once (or slice a VM-owned stack). Toward the shared contiguous value stack listed under the last item.
  - [ ] **`runtime.Tag` allocates a fresh `*Named` per tagging** (208 MB on grafana-openapi): find the hot call sites (coercion/zero/assign re-tagging an already-tagged value with the same typedef) and reuse the existing box when the tag and value are unchanged.
  - [ ] **selector resolution re-searches by name**: `structMember` linearly compares field names then hits `Methods`; `FieldRef.find` walks embeddings breadth-first. Cache the resolved access path (`Def` + name → field index path / method) per type; a dynamic re-dispatch is still needed at interface-typed embedded fields. Related: the `#485` selector lowering item above (`OpFieldRef` 69 MB, `FieldRef.find` ~3% CPU on grafana-openapi).
  - [ ] **global resolution cost per `OpGlobal`**: `resolveGlobalE` calls `fileOf` (`Fset.PositionFor` + filename map) and then `Scopes` + a mutex-guarded `Env.Get` on every access (~5.6% cum CPU on grafana-openapi; `fileOf` itself ~0.9%). An inline cache needs invalidation — `Globals` entries are replaced/deleted by the REPL (`repl.go`, `repl_load.go`), `OpNewGlobal`, and lazy materialization — e.g. an `Env` generation counter; the file must come from a per-instruction file id or resolve descriptor, since `__init__` chunks span several files.
  - [ ] **every local is a heap `*Cell`** (`OpNewLocal`, `prepFrame`): classify captured / address-taken locals at compile time (`UpvalDescs`, `&x` sites) and keep the rest as plain value slots. Overlaps the "frame allocation" item above; the larger follow-up to the double-allocation fix.
  - [ ] **`append` builds a whole zero value to learn the element type** (`builtins.go`, `v.TypeOf(v.ElemZero(rtyp))`): `ElemZero` constructs e.g. a full `Struct` plus a fresh `zeroSeen` map on every append. Resolve the element typedef directly instead: `elemTypedef` is VM-internal, so add e.g. `VMCaller.ElemTypeOf(td)` and migrate the other users of the `TypeOf(ElemZero(td))` idiom the `VMCaller` doc prescribes (`intrinsics.go` JSON paths, `builtins.go`'s zero-size growth check and other `ElemZero` sites). Semantics: today's `et` is lossy (`typeOfValue` maps every integer kind to `int`, `float32` to `float64`, an interface element to nil, `type S string` to `string`) yet output matches go for `[]float32`/`[]S`/`[]any`/`[]int8` appends because later coercion fixes it — a precise typedef newly routes `Convert(any, UConst)` / `Convert(S, UConst)`, so verify by diffing program output against go (casefuzz/difffuzz pins), covering named types, aliases, generics and function-local types. Benchmark scalar, struct, and named/generic appends separately on pre-sized slices (`ns/op`, `B/op`, `allocs/op`), then a mixed run. Synthetic only: no measurable share on grafana-openapi (`append` + `zeroSeen` < 40 MB).
  - [ ] **generic specializations recompile on every call**: `inferBinds` and `instantiateFunc` (`vm/vm.go`) return a fresh `*runtime.Function` without a `Chunk`, so each `Id(x)` re-runs `EnsureCompiled` (100k calls of a trivial `Id[T]`: ~99 ms vs ~50 ms non-generic; grows with body size). Cache specializations keyed by origin function + binds; the key must respect type identity, already-bound binds, and function-local types. Synthetic only: no compile frames in the grafana-openapi CPU profile.
  - [ ] **`Map.Delete` is O(n)** (`runtime/value.go`): it scans and compacts `Order`/`Keys`, so n deletes cost O(n²). Use a key → position index with tombstones and periodic compaction (or swap-with-last if insertion order is not needed); check range-time delete/re-insert semantics. Also: struct/array keys are stringified through `strings.Builder` on every lookup (`CanonicalKey`). Synthetic only: not visible on grafana-openapi.
  - [ ] **later / larger**: a shared contiguous value stack for frames (args without `popArgs` slices, no `BoundMethod` receiver prepend copy); memoizing typedef-derived info (element typedef, basic-kind enum instead of `Zero`'s name switch) kept separate from full typedef interning; a tagged `Value` instead of `any` (int64 boxing was only ~62 MB of the 1.46 GB above); `orderSpecs` (`compile/compile.go`) picks the next spec in O(V²) — a heap would help large packages' first init only.
