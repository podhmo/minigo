Engine-side gaps reported by the real-app storybook exercise ([#1068](https://github.com/podhmo/minigo/issues/1068)); the example workarounds are documented in [the purpose review](./docs/sketch/ja/experiment-storybook.md).

- [x] **`Engine.Bind` should accept or resolve the declared package name** (#1068): `e.Bind("github.com/yuin/goldmark-alert", ...)` registers the package as `goldmark-alert` while scripts refer to it as `alert` → `undefined: alert`; the workaround is `e.BoundOf(path).Name = "alert"` after Bind. Take the name as an option or resolve it automatically.
- [ ] **bound host struct literals are opaque to bound templates** (#1068): `store.Issue{...}` in a story produces script-side structs that bound `html/template` reflection cannot see, so `{{.Issue.ID}}` fails `can't evaluate field ID in type interface {}`. Either document the boundary (value-producing packages must stay source-interpreted) or add an API for real host struct literals.
- [ ] **script-side `fs.FS` cannot cross into bound host code** (#1068): `//go:embed` yields a script `embed.FS` that fails on a bound host function's `fs.FS` parameter, and bound `html/template`/`text/template` lack `ParseFS`; workaround is `fs.ReadFile` + `t.Parse(string(src))`. Bridge script `fs.FS` → host `fs.FS` or accept a script filesystem in `ParseFS`.
- [x] **helper to bind a whole package** (#1068): `Engine.Bind` enumerates each symbol in a `map[string]runtime.Value` by hand (goldmark needed 8 symbols across 4 packages). Provide a whole-package bind helper or at least document the pattern.
- [ ] **incremental source-package caching for session-fork previews** (#1068): `NewSession()` keeps binds warm but re-parses the source package per request (~100-200 ms/req); fine at example scale, but file-level invalidation or a shared incremental cache would matter on larger apps.
- [ ] **missing field in bound `html/template` renders empty instead of erroring** (#1068): `{{.Nonexistent}}` on a script-side struct produces empty output where gc errors `can't evaluate field Nonexistent in type ...`; a typo'd or renamed field is undetectable. Match the stdlib error or add a strict mode — the main diagnostics blind spot for template-heavy use.
- [ ] **story discovery could be a shared helper package** (#1068): the build-tag → story-func scan (now two signatures: print and `func(http.ResponseWriter, *http.Request)` via the `StoryHttp` prefix) is reimplemented per consumer; a small shared `storybook` package outside examples would serve real apps.
