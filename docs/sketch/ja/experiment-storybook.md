# 古典的な MPA に Storybook 的な見た目調整を持ち込む（minigo を使った試み）

`examples/storybook` は、「実データが手元にない状態でも、Go で書かれた MPA の画面や部品を指定した条件でブラウザに描画し、CSS やレイアウトを調整しやすくできないか」というアイデアを、`minigo` を使って試してみた例である。

SPA の開発では、コンポーネントが props だけで描画できるため、API サーバーや実データがなくても状態ごとの見た目を並べて確認・調整する（Storybook のような）進め方が使われている。これと似た仕組みを、サーバー側で HTML を組み立てる古典的な MPA に持ち込めると便利そうなのではないか、という点を探っている。

位置づけとしては、HTML を生成してテストや golden と突き合わせること自体が目的ではなく、「実ブラウザで描画して CSS やレイアウトを直す」反復がどれだけ楽になりそうかを確かめる試みである。

## 1. MPA に Storybook を当てはめてみるとどう見えそうか

MPA では、ページはサーバー側のハンドラーとテンプレートで組み立てられ、表示用データは DB・認証・セッションなどを通って初めて揃う。そのため「特定の状態の画面をブラウザで見ながら CSS を直したい」と思うと、アプリ全体を起動してデータを仕込むところから始めなければならず、手間がかかりやすい。

SPA の Storybook で使われる要素を MPA に置き換えてみると、だいたい次のような対応になりそうに思える。

| SPA の Storybook | MPA で対応しそうなもの |
|---|---|
| コンポーネント | テンプレート（ページまたは部分テンプレート）と render 関数、あるいは HTML ツリーを組む関数 |
| props / args | テンプレートへ渡す表示用の構造体 |
| story（状態ごとの定義） | データ状態ごとの `StoryXXX()` |
| グローバル CSS・decorator | アプリのレイアウトテンプレートと静的アセットの配信 |
| viewport addon | 幅を変えた iframe での並列表示 |
| モックした API 応答 | fake の `Store`、実行時の binding や関数の差し替え |

もっとも、HTML を生成してブラウザで開くだけなら、通常の Go テスト（`httptest.ResponseRecorder` や render 関数の直接呼び出し）でファイルへ書き出す方法でもできる。ただ、通常の Go テストはパッケージ全体がビルドできる必要があり、テストコード自体に呼び出しを増やす手間もある。そこで今回の例では、Go インタプリタの `minigo` を使うとこの体験がどこまで軽くなるかもあわせて試している。

## 2. 最小の形: 引数なしの Story を minigo で直接実行する

ここで置いた最小の仕組みは、「表示条件を用意してアプリの表示コードを呼び、HTML を標準出力へ出すだけの引数なし関数 `StoryXXX()`」を書く、という形である。

```go
//go:build story

package app

import (
    "fmt"
    "strings"
)

func StoryUser() {
    var b strings.Builder
    if err := RenderUser(&b, &User{ID: "1", Name: "Alice"}); err != nil {
        panic(err)
    }
    fmt.Print(b.String())
}
