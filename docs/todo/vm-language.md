- [x] **Real concurrency semantics**: `go` spawns real host goroutines sharing a per-run *process* — each spawned VM is confined to its goroutine while packages, channels and the materialization cache are shared. Verified under `testing/synctest` bubbles (blocking, fake-clock `Sleep`/`After`, detached-goroutine cleanup) and `-race`. Approximations kept: root deadlocks hang like Go's crash rather than trapping (no goroutine preemption), and script cells/maps share storage without script-visible races documented as Go-like UB.

- [x] **`map[string]*[3]int` interior writes still trap** (found while reviewing the map-element lvalue gate, PR #364): `pa["a"][1] = 9` on a map of *pointer-to-array* values is legal Go (the stored pointer derefs to shared storage) but trapped `index assign on *runtime.Struct` — `IndexRef`'s map-element gate only saw the copy-elem vs shared-elem split on the map's element, not the interior pointer hops past it. The root cause was deeper: `makeComposite`'s `KindPointer` case built a `*runtime.Struct` for *any* pointee, so `*[3]int` literals stored a bogus empty struct (even `pa["a"][0]` reads trapped). Pointer composites now build their pointee through the same `compositeOf` kind switch a direct `T{...}` literal uses — `*[3]int` stores `*Cell{*Slice}` — and `setIndex`/`setField` resolve ref chains past a gated map element via `refThrough`.
- [x] **`map[string]struct{F []int}` `m[k].F[i] = v` traps** (accepted leniency of the same gate): a field select off a *copy* struct element must trap for `m[k].F = v`, but writing into the field's own backing store is legal Go when F is reference-shaped. `refThrough` resolves a write's base ref (`IndexRef`/`FieldRef`/`DerefRef` chains) to a `(value, writable)` pair — a struct/array hop inherits its container's writability while a reference-shaped hop restores it — so `m[k].F[i]`, `m[k].P.x`, `*m[k].P = v`, and `m[k].M[k2] = v` all land, while `m[k].F = v`, `m[k].a3[i]`, `m[k].g2.x`, and `m[k].ms2[k2].x` still trap.
