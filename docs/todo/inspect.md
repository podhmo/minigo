# TODO — inspect / package introspection

The `minigo.dev/inspect` index/syntax/value API, `inspect` host-side accessors, and gen-sync introspection.

## Open

- [ ] **Script-side traversal of function bodies** (future work, surfaced by the convert-define experiment): nothing in `minigo.dev/inspect` exposes a function decl's body — index/syntax stop at the signature. Any script-side tool that wants to reason about statements/exprs inside a `func` (linters, flow analysis, codegen that reads rather than executes logic) has no entry point; today only host special forms walk bodies via `*ast.FuncLit` (e.g. convert-define's `mappingWalker`). An inspect body view (statement/expr children, decl-anchored `TypeExpr`s) would be new machinery, not an accessor — deliberately left out of the experiment's gap list.

## Done

- [x] **Package objects / symbol introspection** ([docs/sketch/plan-package-introspection.md](../sketch/plan-package-introspection.md)): the `minigo.dev/inspect` stub package exposes the 3-layer API — index (`PackageOf`/`DirOf`/`FileOf` locators, `Decls`/`Symbol`/`Files`/`Imports`/`UsedSymbols`), syntax (`Fields`/`Methods`/`Signature`/`TypeParams`/`Def`/`Doc`/`Pos`, `TypeExpr` navigation `Children`/`UnRef`/`UnWrap`/`Origin`/`SymbolID`/`Resolve`/`SameType`), and value (`Value`/`TypeOf`); `OwnerOf`/`PathOf`/`SymbolIDOf`/`SymbolOf` map symbols and values back to package and decl (struct instances included; bare type names are a minigo extension, not valid Go). Bound packages enumerate as Kind:`host` pseudo-decls whose `Signature` is recovered from `BuiltinFunc.Target` (the real Go func value, stashed by `h.fn*`); `Package.Standard` splits stdlib from module packages. The REPL gained `:cd <ref>`/`:cd -` (pseudo dot-import with `ImportRef.AllNames` — unexported names resolve) and `:ls [ref]`.
- [x] **inspect: interface type members** — interface decls now read through `Fields` (member elements: named method specs carry `Names` + a FuncType `TypeExpr`, embedded/constraint elements come back `Embedded`) and the two split views from the plan's open question: `MReqs` (method specs only) and `IEmbeds` (embedded/constraint elements as TypeExprs — `~int|~int64` returns one BinaryExpr whose Children are the tilde terms). `SymbolID`/`Resolve` chase embedded names back to their decls.
- [x] **inspect: `SourceOf`** — locator bypassing `Bind` shadows: `SourceOf("strings")` locates and indexes the GOROOT source into a private engine cache (`srcs`, never `pkgs`/`byDir`), so `Symbol`/`Signature`/`Fields` read real decls (param names included) while the bound package keeps answering `PackageOf` and real imports. Unbound paths return the canonical package — `SourceOf == PackageOf` there. Value-layer access on real GOROOT source can still trap on unimplemented constructs; index/syntax layers are the intended use (documented on the stub).

- [x] **`inspect.TypeExpr`: reach non-`Children` sub-expressions** (found by the convert-define experiment; landed on main via #20): `Children()` drops `IndexExpr.X`/`IndexListExpr.X` (generic instantiation bases), `ArrayType.Len`, and `ChanType.Dir`. `withExpr` is now exported as `(*TypeExpr).Sub(ast.Expr)` — host code re-wraps any sub-expression in the same file/pkg context. convert-define's `registerImports`/`getTypeName` use it so generic-typed fields (`pkg.List[T]`) get their base package imported and a qualified rendering. `ChanType.Dir`/`ArrayType.Len` need no child view — `Expr()` exposes them.
- [x] **Host-side `engine.SourceOf`** (landed via #20): `Engine.SourceOf(ctx, path)` reaches the real decl behind a bound shadow. convert-define tried it and reverted — bound-stdlib opacity is the correct consumer policy (a real `time.Time` decl costs laziness, misroutes same-type fields into nonexistent converters, and introspects unexported internals codegen can't use), so `NewHostDecl` pseudo-decls remain.
- [x] **Host-friendly signature access on `inspect.Sig`** (landed via #20): `SignatureOf` keeps the script FFI shape (`*runtime.Slice`); `sig.ParamFields()`/`ResultFields()` return `[]*Field` for host callers. convert-define's hand-rolled `sigFields` unboxer is deleted.

- [x] **inspect host API surface** (issue #19, round-4 notes in [docs/sketch/plan-package-introspection.md](../sketch/plan-package-introspection.md)): `Engine.SourceOf` is exported (bound-shadow bypass for host tools — real decls behind `time.Time`-style bindings reachable via `NewDecl`), `inspect.Sig` gained `ParamFields()`/`ResultFields()` (`[]*Field` unbox of the FFI slices — the host counterpart of `FieldsOf`), `TypeExpr` gained `CanonicalName()` (`"*import/path.Name"` identity spelling, `""` for composites) and `Sub` (re-wraps sub-exprs `Children` misses — generic instantiation bases, array lengths). Host-panic Go stacks were already covered by `Panic.GoStack` (#17) — pinned via the `BoomViaBuiltin` traceback test.

- [x] **inspect: `Implementers` — the index-level subtype lookup** — `inspect.Implementers(p, iface)` returns the type decls of p whose method set covers iface's requirements — named specs plus whatever embedded interfaces pull in transitively: declared, promoted, and alias-borrowed members (`MethodSet` now borrows an alias's target set, since `GB = GreetBase` carries the same methods); signatures compare via `SameType` — params/results/variadicity — so `Add(a,b int) int` satisfies but the `string`-result near-miss and the `[2]int`-not-`...int` miss do not. The method set answers "usable through *T": a pointer-receiver method declared on the type itself still counts. Interface decls satisfy too (an interface embedding the specs, including iface itself), so gen-sync filters `Def(d).Kind == "InterfaceType"` for concrete `-variants=` names; constraint interfaces (`~T`, unions, embedded non-interface types) trap — no value type implements them.
- [x] **gen-sync: bound packages introspectable through `inspect.SourceOf`** — `Explorer.Lookup` resolves a package's decl table via `SourceOf` instead of `PackageOf`, so a bound-shadowed path under the subtree yields its real source decls rather than host pseudo-decls with no index; `TestBoundPackage` `Bind()`s `app/internal/bound` and asserts `BoundRef`→`bound.Marked` earns `requiredgen` anyway.
- [x] **inspect: non-trapping `MReqs`/`IEmbeds`** — both report nil on non-interface *type* decls (non-type decls still trap), so scripts iterate directly without the `Def(d).Kind == "InterfaceType"` pre-gate; gen-sync's `RequiresMethod` dropped the spec-shape ceremony.
- [x] **inspect: structured `Position` view** — `Decl`, `Field`, and `Import` `Pos` fields and `inspect.Pos(d)` return `*inspect.Position{File, Line, Column}` (nil for host symbols) instead of a `"file:line:col"` string; `Pos.String()` keeps the old spelling, so scripts compare fields rather than split text.
- [x] **`inspect`: `SymbolID` as an askable question** — the script-facing `inspect.SymbolID` returns `*runtime.SymbolID` (nil for non-named exprs) instead of `runtime.NIL`-disguised values, so `sid == nil` is valid Go and correct under minigo; scanx's `TypeRefName` keys on the id's fields directly rather than re-parsing `CanonicalName` text.
- [x] **inspect: enum members and value-spec types** — `inspect.DeclType(d)` returns the type expression declared on a var/const decl (the explicit annotation, or the type an empty const spec inherits via `Decl.InheritedType`; nil for untyped specs, trap for other kinds); `inspect.EnumMembers(typeDecl)` collects the package's const decls explicitly typed with it, in source order — the go-scan `IsEnum`/`EnumMembers` shape over the index, linked by `TypeExpr.SymbolID` so untyped and selector-typed consts never match. gen-sync's enum rule dropped its raw-line `HasConstOfType`/`SpecHasType` scan for `len(inspect.EnumMembers(d)) > 0`.
- [x] **inspect: alias vs defined type decls** — `inspect.IsAlias(d)` reads `TypeSpec.Assign` directly, partitioning every source type symbol into alias|defined (orthogonal to enum-ness — a const may still be typed with the alias — and to the underlying shape `Def` reads); gen-sync dropped its raw-line `IsAlias`/`DeclLine`/`IsAliasLine`/`PosFile`/`PosLine`/`LinesOf` helpers.
- [x] **inspect: instantiation bases in `TypeExpr.Children`** — `Children()` leads an `IndexExpr`/`IndexListExpr`'s children with the base (`List[Inner]` → `List` then `Inner`), so recursive walks reach generic containers through instantiations of them; `SameType` now distinguishes `Pair[int]` from `Cage[int]`; gen-sync's `Safe`/`Vault` fixture pins `requiredgen` earned through the base alone; convert-define's `registerImports` dropped its `Sub` special-case.
- [x] **inspect: `TypeFields` — member elements of composite type expressions** — `inspect.TypeFields(te)` returns a struct spelling's fields (names, type, tag) or an interface spelling's elements (named method specs vs Embedded/constraint elements), the TypeExpr-level counterpart of `Fields`; reflect-backed expressions answer too (host structs carry tags; interfaces flatten embeds to method specs). gen-sync's `hasRequiredTag` descends into anonymous composites, so `Inline`/`ListAnon` earn `requiredgen`.
- [x] **inspect: `MethodSet` — flattened method sets with promotion** — `inspect.MethodSet(d)` returns a type's declared methods plus members promoted through embedded fields, walked transitively: `Method{Name, Sig, Decl, Via}` (Decl nil for interface specs, Via names the promoting decl). The set answers "usable through *T": declared methods count with either receiver, while promotion follows the value method-set rule (`struct{ T }` lifts non-pointer receivers, `struct{ *T }`/interface embeds lift all, and a pointer embed on the path down keeps deeper pointer receivers visible); members promote breadth-first so shallower spellings shadow deeper ones; alias and generic-instantiation embeds resolve to the owning decl; cycles terminate; output is sorted by name. gen-sync's `scanx.HasMethod` reads the set, so `EmbedEvent` joins `-variants=` — and interface decls are gated out of it (their own specs are their set, a different question `RequiresMethod` asks).
